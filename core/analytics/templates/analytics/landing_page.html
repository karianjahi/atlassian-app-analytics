Atlassian App Analytics

A customer intelligence prototype for Atlassian Marketplace app vendors. It analyzes customer behaviour, product adoption, churn risk, and customer health.

Go to Dashboard

Background

Atlassian Marketplace vendors build apps that extend products like Jira and Confluence. As customers interact with these apps, they generate usage signals such as installations, configuration events, feature usage, sync failures, and support activity.

This project turns those signals into analytics that help product and customer-success teams understand which customers are healthy, which are at risk, and which may need attention.

Motivation

Raw event data alone is difficult to interpret. Product teams need clear answers:

  • Which customers are actively using the app?
  • Which customers are likely to churn?
  • Which features are being adopted?
  • How is customer health changing over time?
  • Which customers should be prioritized first?

Inspired by codefortynine

This mini-project is inspired by the kind of Atlassian Marketplace apps built by codefortynine GmbH in Karlsruhe.

The prototype is designed around customer behaviour analytics for app portfolios similar to:

  • Deep Clone for Jira
  • External Data for Jira Fields
  • Quick Filters for Jira Dashboards
  • Merge Agent for Jira
  • Snipe-IT for Jira

The project is not affiliated with codefortynine. It is a portfolio prototype built to demonstrate backend engineering, analytics, machine learning, and product thinking.

What the Platform Does

  • Tracks customer usage events
  • Calculates rule-based customer health scores
  • Classifies customers as Healthy, Watch, or High Risk
  • Predicts churn probability using machine learning
  • Shows feature importance for model explainability
  • Stores historical health snapshots
  • Visualizes customer health trends over time
  • Generates automated insights and alerts
  • Forecasts the next health score based on recent trends
  • Ranks customers by churn risk for prioritization

Technical Architecture

The application uses Django as the backend, Django REST Framework for APIs, PostgreSQL for persistence, and JavaScript with Chart.js for interactive frontend rendering.

Machine Learning Layer

The machine learning component uses customer health and behaviour metrics to estimate churn probability. The model is trained with scikit-learn and saved using joblib.

  • Builds a pandas training DataFrame from Django data
  • Trains a logistic regression churn model
  • Evaluates model accuracy
  • Stores ML churn probability per customer
  • Displays model feature importance on the dashboard

Current Limitations

  • Uses synthetic/demo data
  • Uses synthetic churn labels for prototype training
  • Does not yet integrate with real Atlassian APIs
  • Does not yet use real subscription cancellation data
  • No authentication or role-based access yet
  • Forecasting is currently trend-based and simple

Why This Project Matters

This project shows how raw product usage data can become actionable customer intelligence. It combines backend development, REST API design, frontend rendering, analytics, machine learning, explainability, forecasting, and customer-success thinking in one coherent prototype.
